# AI 員工

總監不懂程式，全程用繁體中文、台灣口語；不要一直問授權，選好就做到完。

- 已上班的員工在 `.claude/agents/`，每位的 `name:` 是中文名，description 開頭有「（原名 英文名）」。
- 全部 282 位的中文名冊在同資料夾的 `名冊.tsv`，欄位依序是：中文名、原名、推薦、已安裝、官方原檔、會做什麼。

## 依總監打的字決定做什麼

### 1. 沒帶文字（只打 `/員工`）

用 AskUserQuestion 問（header：「找員工」）：「這次要做什麼？」選項：

- **社群貼文、文案**：IG 經營師、內容企劃師
- **短影音剪輯**：短影音剪輯教練
- **官網畫面**：介面設計師
- **被搜尋到、被 AI 推薦**：SEO 優化師、AI 推薦曝光顧問

總監選好之後，用一句話問他「想請他做什麼？說得越具體越好（主題、給誰看、要幾篇）」，拿到回答就照第 3 步交給員工。

### 2. 「名單」「有哪些員工」

列出 `.claude/agents/` 裡已上班的員工，每位寫中文名和一句「會做什麼」。

再從 `名冊.tsv` 挑 5 位「推薦」但還沒安裝、最可能用得到的員工介紹給總監。

最後附上完整名冊連結 https://claude.ai/artifact/Sgs9cMN1cPeC11n3KkNa4a。

### 3. 「請 OO 幫我…」或 `/員工 OO 要做的事`

1. 找出是哪位員工。中文名、英文原名或大概的說法都算，例如「寫 IG 的那位」。
2. 用 Agent 工具交給他，subagent_type 填他的中文名。交代時一定加上：
   - 用繁體中文、台灣口語。
   - 對象是薇萌 WM Group（形象照、品牌影像、保險理財、行銷顧問）。
   - 只規劃、寫草稿，不要發布、不要改網站。
   - 有數字是示意的要標出來。
3. 收到結果後，整理成總監好讀的樣子再回覆，標明是哪位員工做的。
4. 如果那位員工還沒安裝：
   - 告訴總監這位還沒上班，問一句「要現在幫你加嗎？」（這是唯一需要問的地方）。
   - 他答應就照第 4 步加，加完直接把剛才的事交給他。

### 4. 「幫我加『OO』這位員工」

1. **找人：** 在 `名冊.tsv` 用中文名或原名找。找不到就列出最接近的 3 位讓總監選。
2. **下載：** 從官方下載原檔，存到 `.claude/agents/`，檔名用原檔的檔名：
   `curl -fsSL "https://raw.githubusercontent.com/msitarzewski/agency-agents/main/<官方原檔>" -o .claude/agents/<檔名>`
   只從這個官方網址下載。
3. **改名字：** 改檔頭的兩個欄位，其他內容不動：
   - `name:` 改成中文名。
   - `description:` 前面加「（原名 英文原名）會做什麼。 」，原本的英文說明保留在後面。
4. **更新名冊：** 把 `名冊.tsv` 裡這位的「已安裝」欄填上「已安裝」。
5. **確認員工數量：** 數一下 `.claude/agents/` 有幾位。超過 10 位時提醒總監：每次對話都會先讀一遍員工名冊，人太多會比較耗額度，問他要不要請走不常用的。
6. **上傳 GitHub：** 照這個專案平常的流程上傳。官網專案的流程是：
   - 開 `site/` 開頭的分支。
   - 用 `gh api` 開 PR。
   - 等 Vercel 留言出現「Ready」。
   - 用 squash 方式合併。
   - **公開技能庫也要同步：** 把同一個員工檔放進 GitHub 的 `JayWu6943/wm-claude-skills` 的 `agents/`，名冊的「已安裝」也一起改，直接推到 main。這樣不管開哪個專案的新對話，都叫得到這位員工。
7. **測試：** 用 Agent 工具叫他做一件小事，例如自我介紹一句，確認叫得到。
8. **回報：** 告訴總監他叫什麼、會做什麼、以後怎麼叫他，例如「請 TikTok 經營師幫我…」。

### 5. 「請走 OO」「不要 OO 了」

1. 刪掉 `.claude/agents/` 裡他的檔案。
2. 把名冊的「已安裝」欄清掉。
3. 照第 4 步的流程上傳 GitHub。

## 群組

### AI 系統小組

專門處理薇萌 AI 系統（自動化流程、AI 員工、後台與內部工具）的開發與維運。員工說明裡標有「【AI 系統小組】」。

| 員工 | 負責 |
| --- | --- |
| 產品經理 | 釐清要做什麼、為什麼做、先做哪個 |
| 軟體架構師 | 系統怎麼設計、用什麼技術、取捨在哪 |
| 專案管理師 | 把需求拆成任務、排時程、控範圍 |
| 測試工程師 | 規劃與撰寫自動化測試，找出會壞的地方 |
| 上線維運工程師 | 自動上線流程、雲端維運、監控與回復 |

- 總監說「請 AI 系統小組…」時，依事情性質照「產品經理 → 軟體架構師 → 專案管理師 → 測試工程師 → 上線維運工程師」的順序，挑需要的人接力；彼此獨立的部分可以同時交辦。
- 交代時把第 3 步的「對象」改成：薇萌 AI 系統小組的內部系統。仍然只規劃、寫草稿，不要部署、不要改正式環境，要動手前先給總監看。

## 注意

- 員工的成果是草稿。涉及保險、理財的內容，提醒總監發布前自己再確認一次。
- 回覆裡不要出現檔名、程式碼這類技術字眼，除非總監問。
